NAO ESQUEÇAS DE FAZER O DIAGRAMA

CRIEI AMBIENTE VIRTUAL:
 python -m venv .venv    
 .venv\Scripts\Activate.ps1

INSTALAR AS BIBLIOTECAS COM O COMANDO pip, CORRER COM O COMANDO streamlit run ./app.py

1- EXTRAÇÃO INTELIGENTE DOS DADOS DO REPOSITORIO, FILTRANDO VIA COMPETIÇÃO, EPOCA, E REQUISITOS OBRIGATORIOS (DADOS 360)
A PARTIR DO COMPETITIONS, SACAR O JSON DO MATCH E OS JSONS (EVENTS, LINEUPS, MATCH, THREE-SIXTY) CORRESPONDENTE

Estrutura do Rep:

data/competitions.json — lista de todas as competições/épocas (1 ficheiro pequeno, 80 registos)
data/matches/{competition_id}/{season_id}.json — jogos de cada competição, com metadados ricos (equipas, datas, fase, jornada, etc.) 
(a implementar o filtro seria aqui)

data/events/{match_id}.json — os eventos (ficheiros pesados)
data/lineups/{match_id}.json — 11 iniciais
data/three-sixty/{match_id}.json — os frames 360 (os mais pesados de todos)

2- ESTRUTURAÇÃO DOS DADOS PARA DATAFRAME
O OBJETIVO É DEVOLVER OS JSONS COMO TABELAS MAIS LIMPAS E ESTRUTURADAS

EVENTOS:
  USAMOS O JSON_NORMALIZE PARA DESMONSTAR DICIONARIOS EM COLUNAS PLANAS COM UNDERSCORES
  ORDENAMOS POR INDEX OS EVENTOS PARA FICAREM POR ORDEM TEMPORAL
  EXTRAIMOS CORDENADAS DAS LISTAS E PARTIMO-LAS EM DUAS COLUNAS

LINEUPS:
  FICA UMA LINHA POR JOGADOR

360:
  UM FREEZE_FRAME É A LISTA DAS POSIÇÕES DE TODOS OS JOGADORES NAQUELE INSTANTE
  COM AS TRANSFORMAÇÕES, FICAMOS COM UMA TABELA COM UMA LINHA PARA CADA PAR (EVENTO, JOGADOR),
  E UM DICIONARIO VISIBLE_AREA À PARTE PORQUE É A MESMA PARA TODOS OS JOGADORES NO FRAME 

  A CHAVE QUE LIGA OS DADOS 360 AOS EVENTOS É: 
freeze.event_uuid == events.id

MATCHES:
  ENCONTRA O JOGO E CARREGA OS DADOS DO MESMO ESTRUTURADOS DE FORMA SEMELHANTE AO DESCRITO ACIMA

RESULTA NO OBJETO : Jogo
  QUE TEM AS 4 TABELAS E UNS QUANTOS ATALHOS 


TESTÁMOS O DATAFRAME, QUE JÁ APARECE ESTRUTURADO.


3- CRIAÇÃO DAS MÉTRICAS (TUDO NO CADERNO)
